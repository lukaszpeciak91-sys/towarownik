# KWANT cross-branch inventory — manual Android smoke test

Run on an Android **debug/internal-testing build from this PR**, not the already published AAB. Use a test account only if the existing app requires one; the KWANT public endpoint itself is never logged into. Connect to the internet, open **Taksula → Settings → Working profile**, select **KWANT → Nowy Sącz (205)**, and start a **new Advisor chat**. Do not interpret the historical research numbers below as today's stocks.

1. **Specific branch / product 580.** Ask: `Sprawdź stan produktu 580 w oddziale Zamość`. Ensure the product has first been independently verified in the chat; if not, search for product 580 normally, then repeat. Expect only **Zamość (128)** under **Wskazane oddziały KWANT**, never all 21 branches. Check a real stock number/explicit 0 or unknown, with timestamp and verified unit only when present. On a network inspector, there should be one `GET /api/front/products/580/departments?extended=1` for the location check, no cookies/auth, no redirect follow, and no per-branch fanout.
2. **Different selected branch.** Ask: `Sprawdź dostępność produktu 7027 w Tarnowie`. If not yet verified in this conversation, search for 7027 with normal `find_products` first. Confirm **Tarnów (204)** is the only returned branch. Ask `a w Zamościu?` while the authorization chain is intact; only the now explicitly named branch may appear.
3. **Inflected city / follow-up.** Verify product 7027 and ask `Sprawdź stan produktu 7027 w Białymstoku`. The only branch must be **Białystok (216)**, never Tarnów (204). Follow with `a w Białymstoku?` and `a we Włocławku?` inside a still-authorized stock conversation; these are only valid for their respective canonical live-directory branches. Also check `w Bochni`, `w Piasecznie`, `w Mielcu`, `w Suwałkach` as distinct canonical cities.
4. **National scope.** Ask: `Sprawdź stan produktu 580 we wszystkich oddziałach KWANT` after verifying product 580. Confirm the response includes the live canonical directory (do not assume exactly 21), sorted states if supported, positive and explicit-zero quantities, distinct unknowns and no invented zero for missing rows. Verify **Wszystkie oddziały KWANT**, not OBI markets.
5. **Model-hint isolation and unknown product.** Ask for product 580 **only in Zamość**; a model suggestion of Tarnów or all locations must not cause extra results. Ask `Sprawdź stan produktu 9999 w Tarnowie` when 9999 is not verified; expect rejection/no inventory read rather than a historic 580/7027 substitution.
6. **Two-product safety.** Verify 580 and 7027; ask `Sprawdź stan obu produktów w Zamościu`. Expect a clear statement that the current one-product location tool cannot check both in a single result, **without silently reporting only one** and without cross-branch inventory HTTP. Then explicitly ask for 7027 alone; the current selection must override prior `obu`.
7. **Regression checks.** Search two KWANT product names using normal `find_products` in Nowy Sącz and then another explicitly selected branch. Confirm product cards and selected-branch stock still work independently. Switch to **OBI 075**, verify an OBIK, then check `a w Krakowie?` on a pending location question: OBI labels, market numbers and existing 10-store transport remain unchanged.
8. **Failures and UI.** Test offline/no signal and retry a new USER request only after reconnecting; unknown is not zero, no stale stock/central-stock substitution. If available, test products sold in metres/kg: only an explicit provider-verified unit is shown. Confirm `total_stock` is not displayed as independently verified central stock.

**Canonical ID anchors from verified public KWANT directory:** Zamość 128, Nowy Sącz 205, Tarnów 204, Białystok 216, Bochnia 203, Piaseczno 214, Mielec 206, Włocławek 141, Suwałki 161. Names must be resolved through the current provider directory at runtime; these numbers are smoke-test expectations, not hardcoded routing or stock fixtures.

**Pass criteria:** exact product identity, user-scoped branch response, one public locations GET per product, no credential/cookie headers, no extra branch leaks, honest unknown and unit semantics, accurately typed `obu` limitation, no Android crash, old OBI and `find_products` regressions clean. Capture only sanitized app diagnostics/trace IDs; do not collect cookies, credentials or complete provider HTTP payloads.

**Release gate:** PR remains Draft and unmerged. Automated success does not replace this device-level smoke test.
